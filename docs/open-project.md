# プロジェクトを開く（登録一覧にリポジトリを足す）

**利用者の要件（2026-08-09）:** 「プロジェクトを開くでローカルファイルを開く機能が欲しい。
エディタ、ファイラがそれらに付随して高機能になってほしい」
選んだ形は利用者の判断どおり「**承認つきで登録に足す**」。

⚠️ この文書は**実装より先に順序を決める**ため。認可は順序そのものが守りで、
この repo は順序で2回事故を起こしている（`--allow-exec` の門が自動生成より後ろ /
検査用経路が Host 検証より前）。

---

## 1. 今どうなっているか

`--repo` で起動時に固定した範囲**だけ**が読める（`docs/architecture.md`、
`v0/README.md`「読める範囲は起動時に固定する」）。`?repo=` は
**登録済み一覧との `samePath()` 照合**しか通らないので、HTTP から任意のパスは読めない。
つまり「開く」を足すことは、**この repo が意図的に閉じてきた経路を開ける**ことになる。

## 2. 誰が足せるか（ここが設計の核心）

当初は端末承認と同じ「母艦で合言葉を承認」を考えたが、**測ったら不要だった**。

🚨 **端末の鍵と生の実行トークンは、exec が有効なとき実質同等**（レビュー11で確定し、
`docs/device-approval.md` に明記）。承認された端末は
`POST /api/v0/exec argv=['cat','<任意のパス>']` で**すでに任意のファイルを読める**。
つまり **exec 級の資格情報を持つ相手にとって「リポジトリを登録一覧に足す」は
新しい権限を1つも与えない** — 単なる利便性（画面で見られるようになるだけ）。

| 資格情報 | 足せるか | 理由 |
|---|---|---|
| 生の実行トークン | ✅ | すでに任意コード実行できる。追加は権限の増加にならない |
| 承認された端末の鍵 | ✅ | 同上（exec を通すので `cat` で読める） |
| 書き込みの鍵（`--allow-write` のみ） | ❌ | **新しい範囲への書き込み**を与えてしまう（昇格） |
| 読み取りの鍵（派生秘密） | ❌ | **新しい範囲の読み取り**を与えてしまう（昇格）。広く出回る値 |

**結論: 門は `gateExec`（`--allow-exec` + 生トークンか端末の鍵）。**
合言葉は要らない。**母艦に人が居なくても開ける**ので、スマホから使うという本来の目的にも合う
（合言葉方式にすると「母艦に人が居ないと開けない」= 出先で使えない）。

⚠️ **`--allow-exec` が無いデーモンでは経路ごと閉じる。** 端末登録と同じ判断
（`pairingWhy()` と同型）。理由を返す（黙って 404 にしない）。

## 3. 不変条件

1. 🔒 **`gateExec` を必ず通す。** 読み取り・書き込みの鍵では足せない
2. 🔒 **足せるなら外せること。** レビュー11 の指摘B（`--write` で承認した端末を失効できない）と
   同じ穴を作らない。追加と削除を**同じコミットで**作る
3. 🔒 **git リポジトリのルートだけ。** 検証は**起動時と同じ関数**を通す
   （写すと変異が効かなくなる / 片方だけ緩む。#63 で踏んだ形）。
   ⚠️ `--show-toplevel` は linked worktree ではその worktree を返すので、
   登録名はリポジトリ側（`--git-common-dir` の親）に解決する
4. 🔒 **`samePath()` で重複を潰す。** 同じ場所を別表記で足すとセレクトに2行出て
   **キャッシュも2重**になる（TTL の無効化が片方にしか効かない）
5. 🔒 **監査に残す。** 読める範囲が変わるのは観測ツールとして重大な出来事
6. ⚠️ **足したことを画面に出す。** 黙って増やさない（省略も追加も告知する）
7. ⚠️ **永続化は任意（`--repos-file`）。** 渡さなければそのプロセスだけ。
   渡せば再起動後も残る。**残るなら一覧で見えて消せること**（不変条件2）

## 4. 流れと門の順序

```
[端末] 開く（パスを入力） ──POST /api/v0/repos/add──▶ 1. gateExec（--allow-exec + 生トークン/端末の鍵）
                                                     2. 別オリジン起点を拒否（Sec-Fetch-Site）
                                                     3. パスの形を検証（NUL/長さ/空）
                                                     4. **起動時と同じ正規化**（git ルートに解決）
                                                     5. samePath() で重複を潰す
                                                     6. 監査に残す（repo-add）
                                                     7. 一覧に足す（+ --repos-file に保存）
                                              ◀── 足した結果と、足した後の一覧を返す
```

**順序の理由:**

| 段 | なぜその位置か |
|---|---|
| 1. `gateExec` | **最初**。パスの検証や git の起動より前（認可より前に副作用を起こさない。過去の事故） |
| 2. 別オリジン | 同じマシンの別ポートのページから足させない（#62 と同型。入口は `same-site` を通す） |
| 3–4. 検証 | git を起動するのは認可の後。**起動時と同じ関数**を通す（分岐させない） |
| 6. 監査 | **足す前**に書く（失敗しても「足そうとした」が残る） |

## 5. やらないこと（今回）

- **ディレクトリの一覧・参照（ファイルピッカー）**。作ると「HTTP からファイルシステムを
  歩ける」経路になり、`gateExec` があっても攻撃面として別物（exec は `argv` が監査に残るが、
  ピッカーは読みが残らない）。パスは**打つ**か、母艦の CLI で足す
- **エディタ / ファイラの高機能化**（要件③の後半）。土台（開く）と別の作業なので分ける。
  今のエディタは `git cat-file` 経由の読みと `--allow-write` の枠内の書きに限っている
- **未追跡ファイルの編集**（既に #11 で deferred）

## 6. 測ること（実装と同じコミットで）

- 🔒 読み取りの鍵・書き込みの鍵では足せない（403）。`--allow-exec` 無しでは経路ごと 403
- 🔒 端末の鍵で足せる（exec 級として扱う）
- 🔒 別オリジン起点（`same-site`）では足せない
- git リポジトリでないパス・存在しないパス・NUL 入りは 400 で**理由を返す**
- linked worktree のパスを渡すと**リポジトリ側**に解決される（`?repo=` の照合に通る形）
- 同じ場所を別表記で2回足しても**一覧は1本**（`samePath`）
- 足した直後に `?repo=<新しいパス>` が通る（足した意味がある）
- 外せる（`/api/v0/repos/remove`）。外したら `?repo=` が通らなくなる
- ⚠️ **起動時に渡した `--repo` は外せない**（起動の意図を HTTP から覆させない）
- 監査に `repo-add` / `repo-remove` が残る
- `--repos-file` に保存され、再起動後も残る（渡さなければ残らない）

変異（守りを外すと落ちること）— **実装して全件 KILLED を実測**:

| 名前 | 何を外すか | 測る検査 |
|---|---|---|
| `repo-add-without-exec` | `gateExec` を外す（読み取りの鍵で読める範囲を広げられる） | smoke |
| `repo-add-any-path` | git ルートの検証を外す（任意ディレクトリを登録できる） | smoke |
| `repo-add-no-dedup` | `samePath` の重複潰しを外す | smoke（**bare** で測る。下記） |
| `repo-remove-startup` | 起動時の `--repo` も外せるようにする | smoke |
| `open-ui-no-reload` | 足した後に読み込み直さない（切り替えられない） | **open-check（実ブラウザ）** |
| `open-ui-ignores-input` | 入力欄の値を読まずに送る | **open-check（実ブラウザ）** |
| `serveargs-repos-any-cap` | 控えを `--exec` のときだけ渡す | unit |

## 7. 実装して分かったこと（設計から変わった点）

- ⚠️ **設計の段2「別オリジン起点を拒否」は自前で書く必要が無かった。**
  `gateExec` → `gateMutation` が既に `site !== 'same-origin'` を 403 にしている
  （文言は「別サイト起点の書き込みは拒否します」）。最初は同じ判定をここにも書いたが、
  **到達不能な死んだ守り**だったので削除した（`/pair/*` は入口の認証だけで通るので
  自前の判定が必要だが、こちらは exec の門を通る）。変異 `repo-add-same-site` は
  **書けない**（外しても gateMutation が守るので落ちない）ので一覧から外した。
- 🚨 **`samePath` の重複潰しは、非 bare では差が出ない**（実測）。
  `git rev-parse --show-toplevel` は**大文字小文字・区切り・末尾の `.` をすべて正規化**して
  返すので、どんな表記で渡しても登録名の字面が一致する（= `===` でも潰せる）。
  **bare は git を通さず渡された表記のまま登録する**ので、そこが `samePath` が本当に
  効いている場所。変異が SURVIVED して初めて分かったので、bare で測る形に直した。
- 🚨 **linked worktree のパスを渡すと worktree のまま登録される穴があった**（自分のテストが
  見つけた）。`--show-toplevel` は worktree ではその worktree を返すので、
  `--git-common-dir` の親に解決するようにした（CLAUDE.md のパスの規則どおり）。
  **エージェントが worktree で働くのが本命**なので、ここは本命の構成だけ壊れる形だった。
- 🚨 **`.cmdbar` を再利用したら既存の検査が私の入力欄を掴んだ。**
  `#openbar` の入力欄が DOM 上で先に来たので、`render-check` の
  「`.cmdbar input` が現れるまで待つ」が**コンソール描画前に成立**し、
  さらに IME の検査が**コンソールではなく「開く」の入力欄**を測る状態になっていた
  （守りが壊れていても緑になる静かな誤測定）。検査側を
  「ペインの中 / 監視盤ではない / placeholder が無い」で絞って直した。
