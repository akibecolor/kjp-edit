## 確定した指摘（実質2件）

### 🔴 A. 回転が `token-read` を配り直さず、フック（precheck）が黙って壊れる（SERIOUS ×7観点）

- `rotateExecToken` は `opts.tokenFile`（= `token-exec`）だけを書く。
  読み取り用の派生秘密の配布先 `~/.kjp-edit/token-read` を書くのは
  **`scripts/serve.mjs` の起動時1回だけ**（`server.mjs` に書き込みは1箇所も無い。grep で確認）。
- 派生秘密は生トークン由来（`readSecretOf`）なので回転で変わる（実測: 値が一致しない）。
  → `scripts/precheck.mjs`（**PreToolUse フック = エージェントの安全装置**）は毎回
  `token-read` を読んで提示するので、回転後は **401 → `decide('ask')`** に落ち、
  **衝突の事前チェックがデーモンを再起動するまで黙って止まる**。
- 🚨 **私が書いたコメントが嘘だった:** 「CLI / フック … 影響なし（毎回ファイルを読むので
  回転後の値が入る）」。ファイルは毎回読むが、**その中身が回転後の値に更新されない**。
- 🚨 **復旧案内も嘘だった:** 「`?token=` 付き URL を開き直してください」。
  その URL に載る値も古い派生秘密なので**復旧手段にならない**（新しい値はどこにも出ていなかった）。
- ⚠️ **同じ事故が `serve.mjs:705` に既に記録されていた** —
  「実測: フックが毎回 401 を受け `ask` に倒れて初めて気付いた」。**回転で再発させていた。**
- **直し:** `--read-secret-file` を足し、回転時に `readSecretOf(新トークン)` を 0600 で配り直す。
  ⚠️ 読み取り専用構成では `--token-file` が `token-read` 自身なので、同じパスなら書かない
  （トークンを壊す）。配布先を渡されていない構成では**そう告知する**。
  さらに**新しい読み取り用 URL を stdout に出す**（`opts.port` ではなく実際に listen したポート）。
- **測る:** smoke で「フックと同じ読み方（毎回ファイルを読む）で回転後も 200」
  「配った値が `readSecretOf(新トークン)` と一致」「古い派生秘密は 401」。
  変異 `rotate-skips-read-secret` KILLED。
- ⚠️ **この層を検証するテストが1件も無かった**（`smoke.test.mjs` は `serve.mjs` 経由の
  `token-read` 層を再現していなかった）= 落ちない守り。それも埋めた。

### 🟡 B. 「失効 = 封じ込め」の過大主張（MINOR。私が focus に入れて反証させた点）

- 回転が取り消せるのは「**写された生トークンで HTTP を叩く**」経路だけ。
  相手は既に任意コード実行を得ているので、回転より前に
  **cron / 自動起動の登録 / worktree 内のフックやスクリプト / トークンを常駐メモリに持つ
  別プロセス / 追加した鍵 / 監査ログの改変**を仕込める。**回転はそれらを1つも消さない。**
- つまり「失効 = 封じ込めが本物になる」は成立していない。
  「停止しましたと言って停止していない」と同型の、境界についての嘘。
- **直し:** doc・README・daily-use・コードコメントを
  「**失効は漏れた生トークンを無効化する。exec で確立された永続化は取り消せない**」に訂正。
  影響範囲の表に「**exec で仕込まれた永続化 … 生き残る**」の行を足した。
  疑わしいときは母艦の永続化を人が確認する必要があると明記。
