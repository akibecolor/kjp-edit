# エディタ / ファイラ: 「到達」を直す（#77 の第1増分）

**利用者の要件（2026-08-09）:** 「エディタ、ファイラがそれらに付随して高機能になってほしい」
（要件③の後半。土台の「開く」は `docs/open-project.md` で入った）

⚠️ 要件は **fable の5観点**（作業 / セキュリティ境界 / スマホ / 依存ゼロ / 範囲）で独立に出させ、
**矛盾と過大主張を Opus 側で刈り込んで**この文書にした（`/spec-first` の手順）。
fable が出した 14 must / 10 should / 5 later のうち、**この増分で作るのは2件**。

## 1. 何が問題か（実測で確定した）

**エージェントは作業中ほとんどコミットしない。なのにファイラは
`base...HEAD` の「コミット済み差分」だけを並べる。**

母艦の実測（2026-08-18、`/api/v0/state`）:

```
main              コミット済み差分 0 / 未コミット 変更 0 / 未追跡 0
agent-a           コミット済み差分 0 / 未コミット 変更 0 / 未追跡 0
spare/candidate   コミット済み差分 0 / 未コミット 変更 0 / 未追跡 0
```

つまり**「今まさに書いたものを確認したい」瞬間に、一覧に対象が1つも出ない**。
worktree カードには「変更 N・未追跡 N」と数だけ出るので、
**数は見えるのに中身へ辿り着けない**（この repo が最も嫌う「見えているのに嘘」の隣）。

もう1つ: **未追跡ファイルを見るには編集画面（textarea）に入るしかない。**
スマホでは誤タッチで内容が変わりうるので、「見るだけ」が書き込み UI を経由するのは歪み。

## 2. なぜこの形か（採らなかった案とその理由）

| 案 | 採否 | 理由 |
|---|---|---|
| **未コミット差分を並べる** | ✅ 採る | 上の実測どおり、**導線が切れている唯一の場所**。`git diff` 経由なので fs 直読みも ignored 到達も無い |
| **未追跡を読み取り専用で見る** | ✅ 採る | 既存の門（`requireEditTarget` の `forWrite:false`）をそのまま通せば**権限が1つも増えない** |
| 内容検索（`git grep`） | ❌ 今回やらない | 作業観点が `later` と判定（「出先では名前を知っていることが多い」）。一方で**新しい git 入力・正規表現の DoS・spawn 予算**という最大の攻撃面を開ける。**推測の需要のために攻撃面を開けない** |
| ファイルツリー / `ls-files` 全件 | ❌ 今回やらない | タブが破綻するのは**ファイルが多いとき**だが、実測では 0 件。痛くなってから作る |
| 名前フィルタ | ❌ 今回やらない | 同上（並ぶものが増えてから） |
| 差分の行位置を編集に引き継ぐ | ❌ 今回やらない | 価値はあるが、編集器の置き換えの作りに触るので**別増分**にする |
| 下書きの保持（タブ破棄・通信断） | ❌ 今回やらない | 実需だが、新しい状態の置き場と陳腐化の判定が要る。**別増分**（条件は §6） |
| シンタックスハイライト | ❌ やらない | 依存ゼロと衝突。自前は言語ごとに大きく、**確認作業には行単位の色分けで足りている** |

## 3. 不変条件（壊すなら設計をやり直す）

1. 🔒 **入口を増やしても「パス → 中身」の経路は2本のまま。**
   `/api/v0/blob`（`git cat-file`）と `requireEditTarget`（作業ツリー）だけ。
   新しい「中身を返すエンドポイント」を作らない（**経路を散らしてから認証を入れると1つ忘れる**）
2. 🔒 **未追跡の閲覧は編集と同じ門・同じ capability。** `blob`（読み取りの鍵）に fs 読みを足さない。
   足した瞬間に「read は git オブジェクトまで」の分界が崩れる
3. 🔒 **一覧のデータ源は git だけ。** `fs.readdir` を足さない
   （`docs/open-project.md` §5 で断ったピッカーが裏口で復活する）
4. 🔒 **ignored（`.env`）は今回も対象外。** 未追跡経路の `--exclude-standard` を外さない（#11 のまま）
5. 🔒 **描画は総文字数に対して線形。** 上限で切ったら**見える文字で告知**する
6. ⚠️ **書く力を強化しない。** #77 は「**到達**（探す・開く・読み比べる）」に限る。
   index / refs / remote に触る操作（stage / commit / fetch / rebase）は **#13 に残す**

## 4. 決めたこと（範囲の拡大を明示する）

🚨 **未コミット差分は「読み取りの鍵」にも返す。**

- 今まで read 鍵に返していたのは `git cat-file` 経由の**コミット済みの中身**だけだった。
  ここに **HEAD ↔ 作業ツリーの差分（追跡ファイル）** が加わる = **範囲が広がる**。
- **採る理由:** read 鍵はすでに**リポジトリの全履歴を読める**。同じリポジトリの
  未コミットの変更を隠しても守れるものはほとんど無い一方、
  「**エージェントが今何を書いたか**」はこのツールの中心的な価値。
- ⚠️ **ignored も未追跡も含まれない**（`git diff` は追跡ファイルだけを見る）。
  fs の直読みもしない。
- ⚠️ `README` の「差分 / 全文は追跡されている内容だけ」という記述を**同じコミットで**直す
  （範囲を広げたのに古い記述を残すと嘘になる）。
- ⚠️ 反対なら `--allow-write` の内側に寄せるのは1行（`gateMutation` を通す）。

## 5. 何を作るか

### A. 未コミットの変更をファイラに並べ、差分を見る

- `worktreeStatus` は既に `1 ` / `2 ` を数えている → **変更されたパスも拾う**（spawn を増やさない）
- payload の worktree に `dirtyFiles`（追跡ファイルのみ、上限つき）を足す
- ファイラのタブに **`*名前`** で出す（コミット済み = 素、未追跡 = `+`、未コミット = `*`）
- 選ぶと **HEAD ↔ 作業ツリー**の差分を出す（`/api/v0/diff` に `mode=worktree` を足す。
  **新しいエンドポイントは作らない**）

### B. 未追跡ファイルを読み取り専用で見る

- `/api/v0/file` の `forWrite:false` を**閲覧に使う**（門はそのまま）
- UI は「全文」タブと同じ形（行番号・上限・切ったら告知）で出す。**textarea を開かない**
- 読めない構成（`--allow-untracked` 無し / 書き込みの鍵が無い）では**理由を見える文字で出す**

## 6. 測ること（実装と同じコミットで）

**A について:**
- 未コミットの変更があるファイルが**タブに `*` 付きで出る**（コミット済み・未追跡と見分けが付く）
- 選ぶと **HEAD ↔ 作業ツリー**の差分が出る（`base...HEAD` とは違う内容であることを確かめる）
- 🔒 **ignored なファイルはタブにも差分にも出ない**
- 🔒 **未追跡ファイルは `dirtyFiles` に入らない**（`+` 側の役割と混ぜない）
- 上限で切ったら**件数を告知**する
- 🔒 **作業ツリー差分がリポジトリ設定のコマンドを実行しない。**
  textconv（`--no-textconv`）だけでなく **`.gitattributes` の clean filter** も。
  **別クラスの穴で、フラグでは止まらない**（§9 の BLOCKING）。
  副作用（marker が書かれないこと）で測り、**差分が空でないことも同時に assert する**
- `stats.gitSpawns` が**増えていない**（既存の上限テストで固定）
- 390px で横溢れしない（タブが3種類になる = 過去に1つ足して溢れた場所）

**B について:**
- `--allow-untracked` があるとき、未追跡を選んで**textarea を開かずに中身が読める**
- 🔒 `--allow-write` が無いデーモンでは 403、`--allow-untracked` が無ければ 400（既存の門の文言）
- 🔒 **`blob`（読み取りの鍵）では従来どおり未追跡が読めない**（既存テストを壊さない）
- 読めないときは**理由が見える文字で出る**

## 9. 実装して分かったこと（設計から変わった点・正直に残す）

実装は `docs/editor-filer.md` の §5 のとおり入った（A / B の2件）。設計から変わった点と、
**実装中に検査の欠陥が2件見つかった**ので記録する。

- ⚠️ **§5-B の「理由を出す」は「中身を出す」に変わった。** 設計時点では
  「未追跡は読めないので理由を出す」だったが、B の本題は**編集画面に入らず読める**ことなので、
  実装では読み取り専用の閲覧に置き換えた。実ブラウザの検査（`render-check`）の assert も
  古い挙動（注意書き）を見ていたので、**新しい挙動（中身が出る／textarea を開かない）**に直した。
- 🚨 **`worktreeFileDiff` は `fileDiff` の引数を写した。** 写した瞬間に既存の変異2件
  （`diff-no-textconv` / `diff-no-ext-diff`）が「from が2箇所に一致」で STALE になった。
  一意化したうえで、**写した側の守りにも変異を1件足した**（`worktree-diff-no-textconv`）。
  これを足さないと「新しい方は外しても誰も気付かない」状態になる。

### 🚨 変異が SURVIVED して見つかった、私の検査の欠陥2件

1. **`worktree-diff-no-textconv` が SURVIVED。** 実測すると
   `git diff HEAD -- <path>` は `--no-textconv` を外すと**確かに textconv を実行する**
   （守りは load-bearing）。落ちなかったのは検査の作りが悪く、対象に選んだ `shared.txt` が
   **agent worktree にしか無く main では未追跡**だったため、差分が空で textconv が
   呼ばれていなかった。main で追跡されるファイルを作って測る形に直した。
2. **`dirty-diff-any-worktree` が SURVIVED。** 「登録外の worktree は 400」を
   存在しないディレクトリで測っていたので、照合を外す変異でも**git 側が失敗して 400**になり
   区別できなかった。**別の本物の git リポジトリ**（登録されていない）を用意して、
   門が無ければ 200 で中身が読めてしまう形に直した。

⚠️ どちらも「**400 が返ったから守れている**」と読んでいた形で、
**同じ結果に見える別の原因**を排除していなかった。`/spec-first` の
「主張と検査を1対1に並べる」が効いた例として残す。

### 🚨 実装後のレビューで見つかった BLOCKING 1件（`--no-textconv` では足りなかった）

**`worktreeFileDiff` が `.gitattributes` の clean filter を実行していた。**
`--no-ext-diff` も `--no-textconv` も**これを止めない**（textconv とは別クラス）。
実測で切り分けた:

| 叩いた形 | clean filter |
|---|---|
| `diff --no-ext-diff --no-textconv main...side`（`fileDiff` = コミット間） | 走らない |
| `diff --no-ext-diff --no-textconv HEAD`（`worktreeFileDiff` = 作業ツリー側） | **走る** |
| `status --porcelain=v2 -z`（`worktreeStatus`） | **走る**（8回目のレビューで対処済み） |
| 上に `filterNeutralizeArgs()` を足す | 走らない |

実証: **フラグ0個・ループバックのみ**のデーモンに
`/api/v0/diff?mode=worktree` を1回投げるだけで、コミット済みの `.gitattributes`
（`*.txt filter=pwn`）と `.git/config` の `[filter "pwn"] clean = <コマンド>` から
**デーモンの env ごとコードが走った**（marker に `PWNED env.PATH=…` が書かれた）。
同じ実験で `/api/v0/state` は走らせず、告知も出していた = **守りは既にあったのに
新しい経路が通っていなかった**。

🚨 **これは §9 の「写した守りも測る」を自分でやりながら踏んだ。**
`fileDiff` から引数を写して `--no-textconv` は持ってきたが、
**`worktreeStatus` 側にしか無い守り**（`filterNeutralizeArgs`）は、
別の関数にあったので視野に入らなかった。
**「写し元」を1つに決めると、もう一方の守りが丸ごと落ちる。**
新しい経路を足すときは「**同じ対象（作業ツリー）を読む既存の関数**」を基準にする。

直し方と、それを固定する検査:

- `worktreeFileDiff(cwd, path, filterNames)` に `filterNeutralizeArgs()` を通す
- 呼ぶ側（`/api/v0/diff`）が `repoFilterNames(wtCwd)` を渡す。
  **コミット間の差分では渡さない**（走らないことを実測したので、無駄な 1 spawn を置かない）
- 🔒 潰した filter 名を応答の `filtered` に載せ、**UI が告知する**。
  潰すと作業ツリーの生バイトと index の「掃除済み」の中身を比べるので、
  **実際の `git diff` と行が違いうる**（黙って違うものを見せない）
- 検査は smoke で**副作用**（marker が書かれないこと）を測る。
  ⚠️ 同時に **差分が空でないこと**も assert する — 空だと clean filter は
  そもそも呼ばれず、守りを外しても緑になる（§9 の欠陥1と同じ型を繰り返さない）

| 変異 | 何を外すか |
|---|---|
| `worktree-diff-clean-filter` | 関数側の `filterNeutralizeArgs()` を外す |
| `worktree-diff-filters-not-passed` | 呼び出し側が列挙せず空を渡す（**集約した守りは呼び出し側も測る**） |
