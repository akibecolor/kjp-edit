# エージェント活動の観測（L2 / 実装済み）

**問い**: 「N 個のエージェントを1画面で見る」のうち、**git の状態は見えているが
エージェントが今何をしているかは見えていない**。これをどう埋めるか。

**結論**: **Claude Code が自分で書いているセッション記録を読む。**
PTY も exec も要らない。ただし**リポジトリ外を読む**ことになるので、
これまで守ってきた不変条件を1つ破る。そこを明示的に設計する。

実装: `v0/transcript.mjs`（抽出）+ `v0/server.mjs`（capability と payload）
+ `v0/app.html`（表示）。テストは `v0/transcript.test.mjs` と
`v0/smoke.test.mjs` の「L2」節。

```bash
node v0/server.mjs --watch-agents             # 状態・ツール名・パス・件数（自由文なし）
node v0/server.mjs --allow-transcript-text    # + 発話とコマンド行（--watch-agents を含む）
```

---

## 何が使えるか（実測、2026-08-03）

```
~/.claude/projects/<slug>/<sessionId>.jsonl
```

- `<slug>` は cwd から作られる（`C:\Users\akico\Documents\kjp-editor`
  → `C--Users-akico-Documents-kjp-editor`）。**大文字小文字は正規化されていない**
  （実際に `C--Users-...` と `c--Users-...` が混在していた）→ 照合は case-insensitive で行う
- **1セッション1ファイル。ライブで追記される**（観測中のファイルが 23MB あった）
- 1行1 JSON。使えるフィールド:

| フィールド | 使い道 |
|---|---|
| `cwd` | **どの worktree の活動か**（これが対応付けの鍵） |
| `timestamp` | 最終活動時刻、待機の判定 |
| `type` | `assistant` / `user`（`user` はツール結果の戻りも含む） |
| `message.content[].type` | `tool_use` / `tool_result` / `text` |
| `message.content[].name` | ツール名（実測: `Bash`, `Edit`, `Write`, `PowerShell`） |
| `sessionId` / `uuid` / `parentUuid` | 同一セッションの追跡 |
| ~~`agentId` / `isSidechain`~~ | 🚨 **使えない。** 実データ4本すべてで 0 件（`agentId` はそもそも無い）。サブエージェントの記録は**別ファイル**にある（下の #28 の節） |
| `slug` / `version` / `effort` | 参考情報 |

### ⚠️ `gitBranch` は使わない

実測で **`gitBranch: "HEAD"`** が入っていた（その worktree は `main` に居るのに）。
ブランチ名として信頼できないので、**worktree の対応付けは `cwd` だけで行う。**
`cwd` は `samePath()` で照合する（8.3 短縮名・シンボリックリンク・区切り文字の
差を吸収する既存の関数がそのまま使える）。

## 何を画面に出すか / 出さないか

**記録には会話の全文が入っている。** ここを間違えると、トンネル越しに
繋がる相手へ全部を渡すことになる。

### 段階（T0〜T5）と、どこに線を引いたか

危険度は「本文かどうか」ではなく**何の本文か**で桁が変わる。

| | 中身 | 既定 | `--watch-agents` | `--allow-transcript-text` |
|---|---|---|---|---|
| T0 | 状態（稼働中 / 待機 / 記録なし・経過時間） | — | ✔ | ✔ |
| T1 | 触ったファイルのパス（worktree 相対） | — | ✔ | ✔ |
| T1' | ツール名と件数、サブエージェント本数、`permissionMode` | — | ✔ | ✔ |
| T2 | **コマンド行**（`Bash` / `PowerShell` の `command`） | — | — | ✔ |
| T3 | **アシスタントの発話** | — | — | ✔ |
| T4 | **ユーザのプロンプト** | — | — | ✔ |
| T5 | **ツールの結果**（読んだファイルの中身・コマンド出力）・`thinking` | — | — | **出さない** |

⚠️ **T2（コマンド行）は当初 `--watch-agents` 側に置く設計だったが、
`--allow-transcript-text` 側に寄せた。** 理由は危険度ではなく**テスト可能性**:
`--watch-agents` だけなら「payload に自由文が1文字も無い」という
不変条件をテストで固定できる。その1本が守りの背骨になるので、
自由文をそこに混ぜない方が強い（コマンド行は `curl -H "Authorization: …"`
のような形で秘密を含みうるので、混ぜると背骨が「コマンド行以外は無い」に弱まる）。

### 🚨 T2（コマンド行）は read 権限で出る = そこに載った秘密は read で読める

7回目のレビューで指摘され、実測で確認した:

**`--allow-transcript-text` を付けると、記録された `Bash` / `PowerShell` の
コマンド行が `/api/v0/state` に出る。`/api/v0/state` は Cookie だけで 200 を返す。**
つまり Cookie しか持たない読み取り専用の相手（同じブラウザで開いた他ポートのページ、
トンネルの閲覧者）が、コマンド行に載っている**このデーモンの実行トークン**を
回収できた。README が案内していた起動手順が `--allow-exec --token "$TOKEN"` で、
**値をリテラルで打った回は記録に残る**（実データで `--token` リテラル 42 件、
`x-kjp-token` の値 31 件を確認）。read が RCE に昇格する経路だった。

いまの扱い:

- コマンド行**と発話**を出す前に**秘密をマスクする**（`maskSecrets`）。落とすのは
  (a) **値が分かっているもの**（このデーモンの `--token` と Cookie の導出値）と
  (b) `--token` / `--password` / `api-key` / `Authorization` 等の**直後の語**
- **落としたことは必ず告知する**（コマンド行は `commandMasked`、発話は `masked`。
  黙って消すと「そう打っていない」と誤読される）
- **完全な防御ではない。** 秘密の形は無限にあるので、
  `--allow-transcript-text` は「コマンド行に秘密が載りうる」前提で使うもの。
  **実行トークンは `--token-file` で渡し、コマンド行に値を書かないこと**

🚨 **(b) の区切りは「空白1文字」ではない（8回目のレビュー。SERIOUS）。**
`[ ]+` / `[ ]*` しか見ていなかったので、次の形で**秘密が素通りするのに
「秘密を落としました」と表示していた** = 落としたと嘘をついていた:

| 形 | 何が起きていたか |
|---|---|
| `--token` + タブ + 値 | 何にも当たらず素通り（**告知すら出ない**） |
| `--token \` + 改行 + 値 | **継続の `\` を「値」としてマスク**して `masked:true`。`clip` が `\s+` を空白に畳むので `--token (マスクしました) <秘密>` という綺麗な1行で出た |
| `--password "pass phrase <値>"` | `"pass` だけ落として残りを残す（部分マスク） |
| `authorization: Bearer <値>` | `Bearer` を値と見なして落とし、**トークンを残す** |

いまは (1) **行継続を先に畳み**（sh の `\`+改行 / PowerShell の backtick+改行。
シェルがこの2文字を取り除くので、畳んだ形が実際に実行された形）、
(2) 区切りを `\s` にし、(3) クォートで囲まれた値と認証スキーム語を1つとして食う。
⚠️ 副作用として**過剰にマスクする**ことがある（`--password` が行末にあると次の行の
先頭語を落とす）。過剰マスクは告知付きで情報が減るだけだが、未マスクは秘密が漏れて
**しかも嘘をつく**ので、こちら側に倒している。
⚠️ `clip` の後にもう一度掛ける必要は無い（`clip` は `\s+` を空白1つに畳んで末尾を
切るだけで、`\s` を見ている以上「畳んだ後に初めて成立する形」は無い）。
ただし**テストは `clip` 後の payload も見て固定**してある。

実データ（`~/.claude/projects` の 99 ファイル）での該当数:
`Bash`/`PowerShell` 2518 件のうち改行を含むもの 461 件・タブ 4 件・
`\`+改行の行継続 19 件、**「マスクしたと告知しながら秘密が残っていた」1 件**。
発話 1342 件では**同じ形が 5 件**（発話へのマスク自体が入ったのも 8 回目のレビュー）。

⚠️ この分界（read は読み取りまで）は、**資格情報がコマンド行に載ると崩れる**。
「Cookie は漏れても読み取りまで」という設計の根拠がそこに依存している。

### T5 を出さない理由（機能ではなく前提の問題）

T5 を開けることは「エージェントが読んだ**あらゆるファイルの中身**を出す」ことで、
`git cat-file` 経由のみという不変条件を完全に無効化する。しかも
**予測できない**（`.env` が入るのは「たまたま読んだから」で、
求めたからではない）。だから「`.env` を見たい」という要求の答えにもならない
（それは名前を指定した別経路で設計する。`docs/roadmap-after-v0.md`）。

**永久に禁止ではなく、前提が未達。** 開けるための条件:

1. **読み取り経路にもトークンを要求する。** 今の読み取りは
   Host 許可 + tailnet の membership だけで、アプリ側の認証はゼロ
2. **`/api/v0/session` が無認証でトークンを返すのをやめる**（1が無意味になる）
3. T5 は `--allow-transcript-text` にも含めず**三段目の独立したフラグ**にする
4. **T5 の読み取りを監査ログに書く**（漏れたとき何が露出したか言えるように）

さらに、自己責任で覆えないものが1つある: **MCP 経由で入った他人のデータ**
（Slack / Gmail / Notion のメッセージ）。ここは tool 名の許可リストで切る
（`Read` / `Bash` / `Grep` かつ対象がリポジトリ内のものだけ、など）。

**「何をしているか」だけを出し、「何を言ったか」は既定では出さない。**

### 出す

| | 例 |
|---|---|
| 最終活動からの経過 | `agent-a: 2分前` |
| 状態 | `実行中` / `待機（12分）` / `記録なし` |
| 直近のツール名 | `Bash`, `Edit`, `Read` |
| 操作対象のパス | `v0/git.mjs`（**リポジトリ相対に丸めたもの**） |
| ツール呼び出しの件数 | 直近5分で 23 回 |
| サブエージェントの本数 | `サブ 2/5 稼働`（**別ファイルの mtime で数える**。中身は読まない） |

パスを出す判断: **既にファイラと差分で同じ情報を出している**ので、
新しく漏れる情報ではない。ただし `isSafeRepoPath()` を通り、
かつリポジトリ配下のものだけに限る。

🚨 **パスを出せない理由は5つあり、「外」と言ってよいのは1つだけ**
（8回目のレビュー。SERIOUS）。`repoRelative` が4つの別の事情で同じ `null` を返し、
UI がそれを全部 `(リポジトリ外)` と表示していたので、**リポジトリの中のファイルに
「エージェントがリポジトリ外を触った」と断言していた**。観測ツールとして
安全の判断を誤らせる最悪の嘘なので、`repoRelative` を `{rel, why}` にして
理由を型で分け、表示も分けた（`v0/pathlabel.mjs`）:

| `why` | 画面の文字 | 中身 |
|---|---|---|
| `outside` | `(リポジトリ外)` | 本当に worktree の外（symlink で段数が合わない形も安全側でここ） |
| `root` | `(worktree ルート)` | **worktree ルート自身**。`Grep`/`Glob` の `path` にルートを渡す形で普通に起きる |
| `unsafe` | `(パスを表示できません)` | **中にあるが表示できない形**（先頭が `-` や `:` のファイル名） |
| `unknown` | `(パスを判定できません)` | 判定できなかった |
| （`unresolved`） | `(相対パスの基準が不明)` | 相対パスの基準（レコードの `cwd`）が無い（7回目のレビュー） |

実データ（`~/.claude/projects` の 99 ファイル、パス入力 1181 件）では
`root` が **5 件**あった = 5 回「リポジトリ外を触った」と嘘を表示していた
（`unsafe` は 0 件）。

### 出さない（`--allow-transcript-text` でも交渉不可 = T5）

- **`tool_result` の中身**（ファイルの中身、コマンド出力）
- **トップレベルの `toolUseResult`**（`{stdout, stderr, ...}`）← 別入口
- **`file-history-snapshot` の `snapshot` / `file-history-delta` の `backup`**
  ← ファイルの中身そのもの
- **`attachment`**
- **`thinking`**
- ツール入力のうち**パスとコマンド行以外**（`Edit` の old/new string、
  `Write` の content、`description`）
- **`message` の外にある自由文**（`last-prompt.lastPrompt` /
  `custom-title.customTitle` / `queue-operation.content`）

つまり `--watch-agents` だけなら payload に載るのは
**列挙可能な値と時刻とパスだけ**。発話・コマンド行・ツールの結果は1文字も通さない。

### ⚠️ 「自由文は1文字も通さない」とは言えない — パスは自由文

以前ここに「自由文は1文字も通さない」と書いていたが、**これは成立しない**（#38）。
**パスは本質的に自由文**で、通す条件は「worktree 配下に見える」と
`isSafeRepoPath` を通ることだけ。`isSafeRepoPath` は空白・改行・任意の Unicode を
4096 文字まで許すので、`--watch-agents` だけで recent 12件 × 4096 ≒ **48KB の任意テキスト**が
発話用のフラグ（`--allow-transcript-text`）を経由せずに出ていた。

**引き金は実在する。** エージェントが読んだ README / issue / Web ページの
プロンプトインジェクションが `Read("<repo>/<秘密>")` を1回呼ばせれば、
**失敗した read でも `tool_use` として記録され**、そのまま画面に出る。

いまの扱い:

- パスは **160 文字**で切り、切ったことを `pathClipped` として payload に残す。
  切れたパスは別のファイルを指すか何も指さないので、**UI はリンクにしない**
- **残るリスク（消していない）**: 上限内のパスは出る。
  つまり**ファイル名に入れた文字列は出る**。`git ls-files` と照合して
  「実在する追跡対象だけ出す」ことはできるが、**worktree ごとに git 呼び出しが増える**
  （明示的に禁じている。`CLAUDE.md`）ので採っていない。
  この境界は `v0/transcript.test.mjs` の「長いパスは切って、切ったことを伝える」で
  **挙動として固定**してある（変わったらこの文書も直すこと）

### 🚨 除外方式が成立しないことを実測で確認した（2026-08-03）

上のリストを見れば分かるとおり、**ツールの結果には入口が5つある**。
さらに自由文は `message` の外にもある。形式は Claude Code の内部形式で
公開 API ではないので**フィールドもレコード種別も増える**。

だから実装は**二重の許可リスト**にした:

1. **レコード種別**の許可リスト（`assistant` / `user` / `mode` /
   `permission-mode` 以外は1バイトも見ない）
2. **フィールド**の許可リスト（`text` / `tool_use` 以外のブロックは通さない。
   `mode` やツール名は形（`/^[A-Za-z0-9_.:-]+$/`）で縛る）

⚠️ **`Date.parse` を検証に使ってはいけない。** V8 の緩いフォールバック解析は
`INJECT-SECRET-12345` を**西暦 12345 年**として受け入れる（実測）。
timestamp が自由文の抜け道になっていた。ISO8601 の正規表現で先に縛る。
これは**テストが実装の穴を見つけた**例（`transcript-iso-strict` の変異で固定）。

⚠️ **パスは `path.relative()` で作らない。** 記録の中のパスは worktree の
パスと表記が違いうる（8.3 短縮名 / symlink / 大文字小文字）。素の
`relative()` は `../../..` を返すので、**中にあるファイルを「外」と判定して
見失う**。`relativeInside()`（正規形で判定し、**値は元の表記から取る**）を使う。
正規形をそのまま返してもいけない — Windows/macOS では小文字化するが、
**git はパスの大文字小文字を区別する**ので `git cat-file` が引けなくなる。

## 🔒 破る不変条件と、その代わりに置く制約

これまで読み取り側は **`fs` で読まず `git cat-file` 経由**という不変条件で
「リポジトリ外も未追跡の `.env` も読めない」を担保していた
（`docs/review-write-exec.md`）。**これを破る。**

代わりに置く制約:

1. **既定オフ。** `--watch-agents` を付けない限り経路が存在しない
   （`--allow-write` / `--allow-exec` と同じ形）
2. **読む場所を1つに固定。** `~/.claude/projects/` 配下のみ。
   パスは組み立てずに `readdir` で列挙し、`.jsonl` 以外は開かない
3. **末尾だけ読む。** 既定 256KB。全文パースはしない（23MB あった）
4. **許可リストで抽出する。** 上の表以外のフィールドは payload に入れない
5. **書かない。** 読み取りのみ。記録を消したり触ったりしない
6. **`--watch-agents` を有効にすると起動時に警告を出す。**
   「エージェントのセッション記録（会話を含むファイル）を読みます。
   画面に出すのは活動の要約だけですが、読む対象はリポジトリ外です」

⚠️ **これは `--allow-exec` ほどではないが、読み取りの範囲を広げる変更**なので
capability を分ける。`--allow-write` に相乗りさせない。

## 実装の形

### 探索（spawn 0）

```
worktree の path（既に payload にある）
  → slug に変換（`:` と区切りを `-` に）
  → ~/.claude/projects/<slug>/ を readdir（case-insensitive で照合）
  → mtime が最新の *.jsonl を選ぶ
```

⚠️ slug の変換規則は**推測**なので、変換で当てるのではなく
**`projects/` を1回 readdir して、各ディレクトリの中の1行目の `cwd` で対応付ける**
方が確実（規則が変わっても壊れない）。1行目だけなので安い。

### 読み取り（spawn 0、fs のみ）

- 各ファイルの**末尾 256KB** を読む
- 行に分割し、**先頭の不完全な行を捨てる**（末尾から読むので必ず1行目は途中）
- 新しい順に走査し、`tool_use` を見つけたら最新の活動として採る
- 上限件数（例 200 行）で打ち切る

### コスト（実測、2026-08-03）

**git の起動は 0。** fs の読み取りだけなので `docs/performance.md` の
コスト式（`5 + 3N + P + 1`）は変わらない（スモークテストで
`gitSpawns` が増えないことを固定してある）。

実測（worktree 3本、記録は 24MB の1本、projects 配下 7 ディレクトリ）:

| | |
|---|---|
| `--watch-agents` あり | 220 / 227 / 229 / 236 / 240 ms |
| なし | 211 / 215 / 222 / 226 / 236 ms |
| 読んだ記録 | 256KB（末尾のみ。`tailOnly: true`） |
| payload | 25.9KB |

**差はノイズの範囲**（±15ms の揺れの中に収まる）。支配要因は依然として
git のプロセス起動で、記録の読み取りは効いていない。

読む量を抑えている仕掛け:

- 各プロジェクトの**最新1本だけ**、その**末尾 256KB だけ**
- 先に**先頭 16KB から `cwd` を拾い**、担当の worktree が無ければ末尾は読まない
  （他プロジェクトの記録に 256KB を使わない）
- 走査は 600 行で打ち切り、TTL キャッシュ（1.5秒）に乗る

### 失敗の形（全部「黙って消えない」ようにする）

| | 扱い |
|---|---|
| その worktree の記録が無い | `記録なし`（エラーではない。エージェントを走らせていないだけ） |
| `~/.claude` が無い | `--watch-agents` を無効化し `errors` に理由を出す |
| ファイルが巨大 | 末尾だけ読む。⚠️ **1レコードが巨大な場合は完全な行が0本になる**（実データに 1.25MB / 776KB のレコードが実在）。その場合は上限 4MB まで読み直し、それでも取れなければ**「読めなかった」と伝える**（「記録なし」にしない。#27） |
| 末尾の行が書き込み途中 | JSON パース失敗として捨てる（次のポーリングで読める） |
| 記録が古い（数日前） | `最終活動 3日前` と出す。「今動いている」と誤解させない |
| cwd がどの worktree にも一致しない | 無視（他プロジェクトの記録） |

## この設計で答えられること / 答えられないこと

**答えられる**: 「agent-b は 12 分止まっている」「agent-a は今 `v0/git.mjs` を編集している」
「agent-c はサブエージェントを2本走らせている」「agent-d は記録が無い（まだ走らせていない）」

**答えられない**: 「なぜ止まっているのか」（プロンプト待ちなのか、
考えているのか、落ちたのか）。記録から**待機の理由**までは読めない。
理由が要るなら、そこが初めて PTY（または権限プロンプトの検出）の
検討に値する場面になる。

**つまりこの設計は「PTY が本当に必要かを判断するための材料」でもある。**
これを数日使って「止まっている理由が知りたい」と思うなら PTY、
「止まっていることが分かれば端末を見に行けば十分」なら PTY は不要。

### 実装して分かった追加の材料

`permissionMode` が記録に入っている（実測で `auto`）。列挙値なので既定でも
出せる。**「権限プロンプトで止まっている」の判定に使えるかもしれない**が、
今わかるのは設定値であって「今プロンプトを出している」ではない。
ここが読めるなら PTY はさらに要らなくなるので、数日使いながら
`mode` / `permission-mode` レコードが**待機中にどう変化するか**を見る。

🚨 **`isSidechain` では数えられない（訂正）。** 実データ4本すべてで 0 件で、
これは「使っていないから」ではなく**構造的にそう**だった。
サブエージェントの記録は**親と別のファイル**にある:

```
<slug>/<sessionId>.jsonl                        ← 親
<slug>/<sessionId>/subagents/agent-*.jsonl      ← サブエージェント
<slug>/<sessionId>/subagents/workflows/<run>/agent-*.jsonl
```

その結果、親がサブを走らせている間は親ファイルへの追記が止まり、
UI は稼働中のエージェントを**「待機 N分」と表示していた**（#28）。

対策: `subagents/` を `readdir` して**中身は読まず mtime だけ**で数える
（読めば T5 の入口が増える）。直近に書かれたものを稼働と見なし、
**サブの活動を親の「最後の活動」として採る**。件数の上限は 300 で、
超えたら告知する。
